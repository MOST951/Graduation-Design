# 3.2.2 功能需求分析（重写版）

> 按老师批注：删除原"表 3-1 系统功能模块列表"，改为从普通用户与管理员两类角色出发、对每个功能进行需求描述。

根据图 3-1 与图 3-2 所示的用例图，系统功能需求按角色划分为两个层级：普通用户面向日常舆情查询与分析的七项核心业务功能，管理员在继承普通用户全部权限的基础上额外拥有四项后台管理功能。下面按角色分别展开。

## 一、普通用户功能需求

**（1）数据采集**。普通用户登录后可在前端配置关键词（支持逗号分隔多关键词）、采集数量（上限 50 000 条）与时间范围，提交后由系统异步执行爬虫任务并实时返回采集进度。需求上要求：参数前端校验、任务可随时停止、采集过程中需展示成功数与失败数，以便用户判断是否需要调整关键词；任务结束后应将采集结果按批次归档，便于后续追溯。

**（2）数据预处理**。普通用户可针对已采集的批次发起数据预处理，系统自动完成去噪（URL、@提及、话题标签）、表情符号转写、繁简与全半角统一、Jieba 分词与停用词过滤等步骤，并在结束后输出数据质量报告（有效记录占比、平均文本长度）。需求上要求：小批量支持同步处理便于调试，大批量自动走 Spark 分布式处理；质量得分低于 80% 时应弹出告警提示用户调整规则。

**（3）情感分析**。普通用户可对已清洗的数据发起情感分析，可在"快速模式（仅词典）"与"高精度模式（自适应级联融合，θ=0.7）"间切换。需求上要求：分析结果除情感类别外应返回置信度与分析方法（lexicon / hybrid），便于用户判断结果可信度；当 BERT 模型不可用时应自动降级为词典模式，避免功能中断。

**（4）热点话题分析**。普通用户可查看基于三维度排序（情感 0.4 + 热度 0.4 + 时效 0.2）的热门微博 TOP20 与词云图。需求上要求：提供情感、热度两个权重滑块支持用户按需调整（时效自动补齐），调整后排序结果应实时刷新；词云中的关键词可点击，用于级联筛选相关微博，便于深入挖掘话题脉络。

**（5）实时舆情监控**。普通用户可订阅指定关键词，系统按 5 秒周期更新该关键词的情感分布与热门关键词排行，并按负面占比 30%/45%/60% 三级阈值触发黄/橙/红预警。需求上要求：预警触发时页面顶部需弹出醒目提示并支持浏览器通知，预警事件须写入历史表便于事后回溯。

**（6）数据流水线管理**。普通用户可一键执行"采集→清洗→分析→排序→入库"全流程，系统记录每个阶段的状态、耗时与异常信息。需求上要求：支持同步（小批量）与异步（大批量）两种执行模式；当某阶段失败时应支持断点续跑，仅从失败阶段重启，避免重复采集造成的资源浪费。

**（7）可视化展示**。普通用户可在统一可视化面板查看情感分布饼图、情感趋势折线图、热点词云、传播网络图等。需求上要求：所有图表支持鼠标悬停 tooltip 与区间缩放，支持按时间范围、关键词、情感类别筛选，并支持导出为 PNG 图片或 PDF 文件，便于用户在报告中复用分析结果。

## 二、管理员额外功能需求

**（1）用户管理**。管理员可对系统内普通用户进行新增、禁用、重置密码与角色调整等操作。需求上要求：密码采用 BCrypt 加密存储，所有管理员操作须写入审计日志，便于安全追溯。

**（2）Spark 参数配置**。管理员可在线调整 Spark 作业的 executor 内存、核心数、并行度与默认 batch_size 等关键参数。需求上要求：配置项保存在 `system_configs` 表中，修改后通过事件总线广播至各服务即时生效，无需重启容器；并应记录修改前后的取值便于回滚。

**（3）数据库与系统参数配置**。管理员可维护 MySQL 与 HBase 的连接信息、词典路径、情感阈值 θ、三维度排序权重等系统参数。需求上要求：所有参数变更须做合法性校验，避免因配置错误导致服务不可用；敏感字段（如数据库密码）需脱敏展示。

**（4）系统日志查看**。管理员可按级别（INFO/WARNING/ERROR）与关键词检索系统运行日志、采集日志与审计日志。需求上要求：日志支持按时间倒序分页展示，并提供导出功能；ERROR 级别日志应在管理界面顶部以红色徽章提示总数，便于运维及时响应。

综上，系统功能需求覆盖了从数据采集、处理、分析、展示到后台运维的完整链路，普通用户与管理员两类角色的权限边界清晰，满足舆情监测业务的核心诉求。
