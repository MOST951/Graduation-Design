## 摘要（约 320 字）

微博作为社会舆论的重要载体，其海量、高速、高噪声的数据特性对实时监测与情感分析提出了挑战，传统单机处理模式难以满足扩展性与实时性要求。为此，本文设计并实现了一套基于 Spark 伪集群的微博舆情情感分析系统。系统采用前后端分离与双后端微服务架构：Vue3 前端集成 ECharts 实现可视化，Java Spring Boot 后端负责用户认证、采集任务管理与 Spark 作业调度，Python Flask 后端承担情感分析、三维度排序与数据流水线等核心算法。算法层面提出自适应级联融合策略（词典-ChineseBERT 级联混合，置信度阈值 θ=0.7），在 1 万条隔离测试集上取得 85.73% 准确率（Macro F1 = 0.8582），相比纯 BERT 仅下降 2.06 个百分点而显著节省推理开销；并提出情感强度-传播热度-时效性三维度排序模型，NDCG@10 达 0.9051，相比单热度基线提升 46.4%。系统通过 Docker Compose 在单机环境下编排 12 个容器模拟分布式集群，经 Spark 性能优化后数据处理效率提升 63.5%，连续运行 3 小时以上稳定无异常。

**关键词**：微博舆情；情感分析；Spark 伪集群；ChineseBERT；三维度排序

## Abstract（约 300 字）

Weibo serves as a major carrier of public opinion. Its massive, high-velocity and noisy nature challenges real-time sentiment analysis, and single-machine processing fails to meet scalability requirements. This paper designs and implements a Weibo sentiment analysis system on a Spark pseudo-cluster. The system adopts a front-end / back-end separated architecture with dual back-ends: a Vue3 front-end with ECharts, a Java Spring Boot service for authentication and Spark job scheduling, and a Python Flask service for sentiment analysis, ranking and pipeline orchestration. An adaptive cascade-fusion strategy (lexicon–ChineseBERT, threshold θ=0.7) achieves 85.73% accuracy (Macro F1 = 0.8582) on a 10 000-sample isolated test set, only 2.06 percentage points below pure BERT while saving substantial inference cost. A tri-dimensional ranking model combining sentiment intensity, propagation popularity and timeliness reaches NDCG@10 = 0.9051, a 46.4% gain over the popularity-only baseline. Twelve containers orchestrated by Docker Compose simulate a distributed cluster on a single host; Spark optimisation improves throughput by 63.5%, and the system runs stably for over 3 hours.

**Keywords**: Weibo public opinion; sentiment analysis; Spark pseudo-cluster; ChineseBERT; tri-dimensional ranking

# 第 1 章 绪论（约 2 000 字）

## 1.1 研究背景及意义

随着移动互联网与社交媒体的快速发展，微博已成为国内公众表达观点、传播信息与形成舆论的核心平台，每日产生海量短文本数据，蕴含丰富的情感倾向与舆情动态。对微博数据进行实时、高效、准确的情感分析，可为政府决策、企业品牌监测、公共事件应对与社会治理提供重要的数据支撑。然而，微博数据具有海量、高噪声、短文本、网络用语多、更新速度快等特点，传统单机处理方式在速度、扩展性与准确性上均难以满足要求。

Spark 分布式计算框架凭借内存计算与流处理优势，非常适合大规模舆情数据处理；采用 Spark 伪集群方案，能够在单机环境下模拟分布式运行，降低实验硬件门槛，便于教学与科研场景复用。本文借鉴已有微博舆情分析系统的分层架构思路与 ChineseBERT 在中文情感分类中的应用经验，融合词典方法与深度模型，构建情感、热度、时效三维度排序策略，实现数据采集、清洗、存储、分析、可视化全流程，具有较高的工程应用与教学价值。

## 1.2 国内外研究现状

### 1.2.1 国内研究现状

国内微博情感分析研究经历了从词典方法、传统机器学习到深度学习的演进。王勇等[1] 利用极性词典结合程度副词与否定词规则实现中文微博情感分类，方法计算高效但难以处理复杂语义。王春东等[2] 系统综述了微博情感分析方法，指出从词典到 CNN、LSTM、BERT 的技术路线。龙宇等[8] 提出 Self-Attention 与 TextCNN-BiLSTM 融合模型，兼顾序列建模与局部特征。朱士成、钱钢[7] 基于 ChineseBERT 进行双通道隐式情感分类，验证了字形与拼音特征的有效性。在系统层面，沈鹏飞[3]、霍英等[6] 分别基于 Spark 构建了微博数据分析与舆情分析系统，但多依赖真实集群部署。

### 1.2.2 国外研究现状

国外社交媒体情感分析研究多围绕 Twitter、Instagram 等平台，技术演进同样经历了词典—机器学习—深度学习—预训练模型的过程。Devlin 等[10] 提出的 BERT 通过掩码语言模型与下一句预测在大规模语料上预训练，刷新多项情感任务的最佳成绩；Sun 等[11] 提出的 ERNIE 引入实体级与短语级知识掩码，在中文任务上表现领先。近年模型融合成为重要方向，He[12] 提出的双联合分类器将 RoBERTa 与 BERT 集成并辅以 BiGRU，显著优于单一模型；Bouassida 与 Mezali[13] 指出，纯 Transformer 在处理网络用语与缩写时易忽略细微顺序依赖，结合 BiLSTM 等序列模型可弥补不足。融合多种模型优势已成为提升社交媒体情感分析性能的有效途径。

### 1.2.3 现有研究的不足

综合国内外现状，可归纳出以下不足：一是单一模型难以同时兼顾精度与效率，词典方法准确率约 72%–78%，深度方法可达 83%–89% 但推理成本高；二是排序策略多为单一热度维度，容易遗漏情感强烈但传播尚未扩散的样本，对舆情预警价值有限；三是现有 Spark 微博系统多依赖真实多节点集群，硬件门槛较高，不利于教学与个人研究复现；四是中文微博的字形、拼音等语言特征利用不足。表 1-1 给出常见情感分析方法对比。

# 第 2 章 相关理论与技术介绍（约 800 字）

## 2.1 大数据处理框架

### 2.1.1 Spark 计算框架

Spark 是一种基于内存计算的通用分布式计算框架，相比 Hadoop MapReduce 引入了弹性分布式数据集（RDD）与内存计算机制，显著提升迭代与交互式查询效率。Spark 采用 Master/Slave 架构，核心组件包括 Spark Core、Spark SQL、Spark Streaming 与 MLlib。本系统采用 Spark 伪集群模式，在单台物理服务器上通过 Docker Compose 模拟多节点分布式环境，由 Master 节点负责调度，多个 Worker 节点执行计算任务，数据持久化于 HDFS，从而以较低硬件成本复现真实集群行为。Spark 伪集群架构如图 2-1 所示。

**图 2-1 Spark 伪集群架构图**

### 2.1.2 HDFS 存储框架

HDFS 是 Hadoop 体系中的分布式文件系统，采用 Master/Slave 架构，由 NameNode 管理元数据，DataNode 存储数据块。其核心特征是数据分块存储、多副本机制与一次写入多次读取。本系统利用 HDFS 存放原始微博数据与清洗后的中间结果，按日期分区组织，便于批量分析与历史回溯。

## 2.2 文本预处理与情感分析方法

### 2.2.1 数据采集与文本预处理

微博数据采集通常有官方 API 与模拟登录爬虫两种方式，本系统采用 "API 为主、爬虫为辅" 的混合策略，对反爬机制通过 User-Agent 轮换与请求限流应对。文本预处理步骤包括去除 HTML、URL、@提及与话题标签，繁简转换与全角转半角，使用 Jieba 分词并加载领域词典，过滤停用词，以及表情符号转写。

### 2.2.2 情感分析方法

基于词典的情感分析依赖情感词典与规则库，推理速度快、可解释性强，但难以处理复杂语义，公开数据集准确率通常在 72%–78%。基于深度学习的情感分析以 BERT 类预训练模型为代表：BERT 通过双向 Transformer 编码与掩码语言模型预训练后微调，可适配情感分析等下游任务；ERNIE 针对中文设计实体级与短语级掩码，提升语义单元学习能力；ChineseBERT 在 BERT 基础上引入字形与拼音嵌入，增强对网络用语和未登录词的鲁棒性。词典方法计算开销低但精度有限，深度模型准确率高但耗时较长，本文将两者级联使用以平衡精度与效率。

## 2.3 本章小结

本章梳理了系统涉及的关键理论与技术：大数据侧介绍了 Spark 体系结构、伪集群部署与 HDFS 存储原理；文本侧说明了爬虫采集、预处理流程与词典/深度两种情感分析方法的优劣，并交代了本文采用自适应级联融合策略的基本思路。

## 4.2 算法模型设计

### 4.2.1 情感分析级联融合模型

为兼顾准确率与计算效率，本文设计自适应级联融合策略：先由词典方法对全部文本进行快速初筛，对高置信样本直接输出结果；对低置信样本再调用 ChineseBERT 进行深度分析，并将两种结果做自适应加权融合。整体流程见图 4-3。

**图 4-3 自适应级联融合策略流程图**

**词典分析**综合 HowNet、大连理工情感词汇本体、自建表情/否定/程度副词词典构建覆盖约 28 000 词条的领域词典，对分词后的文本逐词匹配，得到正负情感得分与置信度 conf<sub>lex</sub>。

**ChineseBERT 分析**以 hfl/chinese-bert-wwm-ext 为基座，在合并后的三分类微博情感数据集（约 10 万条）上微调，训练参数 batch size = 32、learning rate = 2e-5、epochs = 3、max length = 128，第二轮取得最佳验证准确率 87.24%。模型最后一层 logits 经 Softmax 得到三类概率 (p<sub>−</sub>, p<sub>0</sub>, p<sub>+</sub>)，情感得分 S<sub>bert</sub> = p<sub>+</sub> − p<sub>−</sub>，置信度取三类概率的最大值。

**级联门控判断**。词典分析完成后，系统按下式决定是否调用 BERT：

$$
\text{useBERT} =
\begin{cases}
\text{False}, & \text{conf}_{lex} \ge \theta\ \text{且}\ n_{match} \ge n_0 \\
\text{True}, & \text{其他情况}
\end{cases}
\tag{4-1}
$$

其中 θ 为置信度阈值，n<sub>0</sub> 为高置信情感词数量阈值。当词典置信度与匹配词数量均足够时，认为词典判断已可靠，直接输出，避免不必要的 BERT 推理开销。本文取 θ = 0.7，n<sub>0</sub> = 2。

**自适应加权融合**。当 useBERT 为真时，词典与 BERT 的得分按下式融合：

$$
S = \alpha \cdot S_{lex} + (1 - \alpha) \cdot S_{bert}
\tag{4-2}
$$

其中 α 为动态权重，基础值 α<sub>0</sub> = 0.4，根据词典置信度、匹配词数量、文本长度与 BERT 置信度等因素动态调整后归一化到 [0.2, 0.8]，确保两种方法均有最低贡献。最终情感类别由融合得分 S 确定，并记录融合方式（rule_only / bert_only / hybrid）以增强可解释性。

### 4.2.2 情感-热度-时效三维度排序模型

为弥补单一热度排序对潜在舆情的遗漏，本文提出三维度综合排序模型，从情感强度、传播热度与时效性三个维度对每条微博进行评价：

$$
R = \alpha \cdot S_{norm} + \beta \cdot H_{norm} + \gamma \cdot T_{norm}
\tag{4-3}
$$

其中 S<sub>norm</sub> 为情感强度归一化值（取 |S| 后压缩到 [0,1]），H<sub>norm</sub> 为传播热度归一化值（基于转发、评论、点赞数对数压缩后线性归一），T<sub>norm</sub> 为时效衰减值（按发布时间相对当前的指数衰减得到）。综合权重 α、β、γ 经 §4.2.3 实验确定为 0.4、0.4、0.2。

### 4.2.3 权重确定与实验验证

通过网格搜索在验证集上对 α、β、γ 在 {0.2, 0.3, 0.4, 0.5} 取值范围内组合（满足 α+β+γ=1）进行调优。以 NDCG@10 为评估指标，最优组合为 α=0.4、β=0.4、γ=0.2，对应 NDCG@10 = 0.9051，相比仅热度的传统方法（NDCG@10 = 0.6182）提升 46.4%。该组合在情感强度与传播热度间取得平衡，同时通过 γ=0.2 引入适度时效偏置，避免热门旧帖长期占据排序前列。

三维度排序作业读取 `sentiment_analysis_results` 表与 `weibo_core_data` 表，先以 DataFrame join 拼接得到包含情感得分与互动指标的宽表，再分别计算情感强度归一化、互动热度归一化与时效衰减三列，最终按公式 (4-3) 加权得到综合得分，使用 `Window.partitionBy(...).orderBy(...)` 进行分区排序后写回 `tri_dimension_ranking` 表，作业流程见图 6-16，监控界面见图 6-17。整个排序作业在 75 条数据上耗时 0.01 秒，在 1 万条数据上耗时约 1.2 秒，写入 HDFS + HBase 的 IO 占主要开销。Spark 的窗口函数与列式存储 Parquet 中间结果显著降低了多次扫描成本，相比单机 Pandas 实现，1 万条规模下耗时下降约 3.6 倍。

### 6.3.5 实时流处理实现

实时舆情监控基于 Spark Structured Streaming，将爬虫持续写入的 JSON 文件夹作为流式输入源，按 30 秒为微批触发清洗、级联情感分析与三维度排序，输出结果通过 `foreachBatch` 写入 HBase 并由 Flask 后端推送至前端。当某关键词的负面比例在 5 分钟滑动窗口内超过预设阈值时触发告警写入 `realtime_alerts` 表。实测端到端延迟稳定在 35–45 秒，满足舆情预警的时效需求。

## 6.4 本章小结

本章实现了系统三大模块。前端以概览方式呈现 8 个功能模块，重点描述了三处关键交互；双后端通过 JWT 认证与 RESTful 协同完成业务与算法的物理隔离；大数据处理模块基于 12 容器 Docker Compose 构建 Spark 伪集群，依次实现了分布式预处理、级联情感分析、三维度排序与实时流处理，充分体现了分布式架构在精度与吞吐方面的工程价值。

# 总结与展望（约 400 字）

本文设计并实现了基于 Spark 伪集群的微博舆情情感分析系统，采用分层模块化架构与双后端微服务，覆盖数据采集、清洗、存储、分析、可视化全流程。情感分析方面提出自适应级联融合策略（词典-ChineseBERT 级联混合，θ=0.7），在 1 万条测试集上取得 85.73% 准确率，相比纯 BERT 仅下降 2.06 个百分点而显著降低推理开销；话题排序方面提出情感-热度-时效三维度模型，NDCG@10 达 0.9051，相比单热度基线提升 46.4%。系统通过 Docker Compose 编排 12 个容器在单机环境下复现了 Spark 分布式集群行为，经性能优化后数据处理效率提升 63.5%，连续运行 3 小时以上稳定无异常。未来工作将围绕四个方向展开：引入增量学习以适应微博语言演变；探索模型量化与知识蒸馏以进一步降低推理资源消耗；扩展系统支持图像与视频等多模态内容分析；将伪集群方案推广至真实多节点集群以验证更大规模数据下的处理能力与稳定性。
