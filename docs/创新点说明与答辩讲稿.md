## 二、创新点详细说明

### 创新点1：情感-热度双维度排序模型

#### 1.1 问题背景

传统舆情分析系统存在以下局限：
- **单一维度排序**：仅按热度或情感单独排序，无法综合评估
- **忽略时效性**：未考虑信息传播的时间衰减特性
- **缺乏用户影响力**：未区分普通用户与意见领袖的影响差异

#### 1.2 技术方案

**核心公式**：
```
DualScore = α × SentimentNorm + β × HeatNorm

其中：
- α + β = 1（权重约束）
- SentimentNorm ∈ [0, 1]（归一化情感得分）
- HeatNorm ∈ [0, 1]（归一化热度得分）
```

**热度计算模型**：
```
HeatScore = InteractionScore × TimeDecay × InfluenceFactor

InteractionScore = log(1 + w₁×转发 + w₂×评论 + w₃×点赞)
TimeDecay = exp(-λ × Δt)，λ = ln(2) / 半衰期
InfluenceFactor = log(1 + 粉丝数) / log(base) × 认证加成
```

**四象限分类法**：

```
                    高情感
                       │
    ┌──────────────────┼──────────────────┐
    │                  │                  │
    │   潜在风险        │    重点关注       │
    │  (高情感低热度)    │   (高情感高热度)   │
    │                  │                  │
低热度 ─────────────────┼─────────────────── 高热度
    │                  │                  │
    │   一般内容        │    热门中性       │
    │  (低情感低热度)    │   (低情感高热度)   │
    │                  │                  │
    └──────────────────┼──────────────────┘
                       │
                    低情感
```

#### 1.3 技术先进性

| 对比维度 | 传统方法 | 本系统方法 | 优势 |
|---------|---------|-----------|------|
| 排序维度 | 单一（热度或情感） | 双维度融合 | 综合评估更全面 |
| 时效性 | 不考虑 | 指数衰减模型 | 反映信息生命周期 |
| 用户影响力 | 不区分 | 粉丝数+认证加成 | 识别意见领袖 |
| 可配置性 | 固定参数 | 动态权重调整 | 适应不同场景 |

#### 1.4 代码实现亮点

```python
# 双维度得分计算（核心代码）
class DualDimensionModelV2:
    def calculate_dual_score(self, sentiment_normalized, heat_normalized):
        """
        双维度综合得分计算
        公式：DualScore = α × Sentiment + β × Heat
        """
        return (
            self.config.sentiment_weight * sentiment_normalized +
            self.config.heat_weight * heat_normalized
        )
    
    def classify_quadrant(self, sentiment_norm, heat_norm):
        """四象限分类"""
        high_sentiment = sentiment_norm >= self.config.sentiment_threshold
        high_heat = heat_norm >= self.config.heat_threshold
        
        if high_sentiment and high_heat:
            return Quadrant.HIGH_SENTIMENT_HIGH_HEAT  # 重点关注
        elif high_sentiment and not high_heat:
            return Quadrant.HIGH_SENTIMENT_LOW_HEAT   # 潜在风险
        elif not high_sentiment and high_heat:
            return Quadrant.LOW_SENTIMENT_HIGH_HEAT   # 热门中性
        else:
            return Quadrant.LOW_SENTIMENT_LOW_HEAT    # 一般内容
```

### 创新点2：混合情感分析方法

#### 2.1 问题背景

| 方法 | 优点 | 缺点 |
|------|------|------|
| 词典方法 | 速度快、可解释性强 | 精度有限、难处理复杂语义 |
| 深度学习 | 精度高、理解上下文 | 计算资源消耗大、速度慢 |

**核心问题**：如何在精度和效率之间取得平衡？

#### 2.2 技术方案

**混合融合策略**：

```python
class HybridSentimentAnalyzer:
    """
    混合情感分析器
    
    融合策略：
    1. weighted: 加权平均（默认）
    2. confidence: 置信度选择
    3. cascade: 级联判断
    4. voting: 投票机制
    """
    
    def _weighted_fusion(self, lex_score, lex_conf, bert_score, bert_conf):
        """
        加权融合策略
        
        根据置信度动态调整权重：
        - 高置信度结果获得更高权重
        - 自适应平衡两种方法的贡献
        """
        # 动态权重计算
        total_conf = lex_conf + bert_conf
        lex_w = self.lexicon_weight * lex_conf / total_conf
        bert_w = self.bert_weight * bert_conf / total_conf
        
        # 归一化
        total_w = lex_w + bert_w
        lex_w /= total_w
        bert_w /= total_w
        
        # 融合得分
        final_score = lex_w * lex_score + bert_w * bert_score
        return final_score
```

class PartitionOptimizer:
    """分区优化器"""
    
    RECORDS_PER_PARTITION = 100000  # 每分区推荐记录数
    
    @staticmethod
    def calculate_optimal_partitions(record_count, avg_record_size=1000):
        """根据数据量计算最优分区数"""
        partitions_by_count = record_count // RECORDS_PER_PARTITION
        total_size_mb = (record_count * avg_record_size) / (1024 * 1024)
        partitions_by_size = int(total_size_mb / 128)  # 128MB/分区
        return min(1000, max(partitions_by_count, partitions_by_size))
    
    @staticmethod
    def handle_data_skew(df, skew_column, salt_buckets=10):
        """数据倾斜处理（加盐法）"""
        return df.withColumn(
            "_salt", (F.rand() * salt_buckets).cast("int")
        ).withColumn(
            "_salted_key",
            F.concat(F.col(skew_column), F.lit("_"), F.col("_salt"))
        )

## 七、常见问题准备

### Q1: 为什么选择α=0.5, β=0.5作为默认权重？

> 这是一个平衡的默认值，实际应用中可根据场景调整：
> - 品牌监控：α=0.7（更关注情感）
> - 热点追踪：β=0.7（更关注热度）
> 
> 系统支持用户动态调整，这正是我们的创新点之一。

### Q2: 混合方法的融合策略如何选择？

> 我实现了四种策略：
> 1. **weighted**（默认）：适合大多数场景
> 2. **confidence**：当两种方法差异大时使用
> 3. **cascade**：先用词典快速筛选，不确定的再用BERT
> 4. **voting**：适合需要高可靠性的场景

### Q3: Spark伪集群与真实集群的差异？

> 主要差异在于：
> 1. 伪集群所有进程在单机，真实集群分布在多节点
> 2. 伪集群受单机资源限制，真实集群可横向扩展
> 
> 但代码层面完全兼容，只需修改`spark.master`配置即可迁移。

### Q4: 系统的性能瓶颈在哪里？

> 主要瓶颈：
> 1. BERT推理速度（已通过批处理和FP16优化）
> 2. 单机内存限制（已通过缓存策略优化）
> 
> 未来可通过部署GPU服务器和真实集群进一步提升。

### Q5: 四象限阈值如何确定？

> 默认使用0.5作为分界点，实际应用中可以：
