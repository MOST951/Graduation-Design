## 📌 答辩问答储备

**Q1：为什么三维度排序结果实体要单独建表，而不是把字段加到情感分析结果表里？**

A：① 一条微博可在不同批次、不同权重下产生多次排序结果，单独建表便于历史复算与策略对比；② 排序计算依赖外部参数（α/β/γ 权重、半衰期），需要持久化当次计算上下文以保证可追溯；③ 排序结果是高频读取的展示数据，独立建表可建立专门索引（如 `composite_score`、`ranking_position`）优化查询性能。

**Q2：为什么需要 HBase？MySQL 不够用吗？**

A：① 微博数据具有"字段稀疏、单条记录字段数差异大"的特性（部分微博有图片/视频/位置/话题，部分没有），HBase 列族稀疏存储可有效节省空间；② 历史数据规模可达千万至亿级，MySQL 单表查询性能下降明显，HBase 通过 RowKey 前缀扫描可高效定位；③ HBase 写入吞吐量更适合实时流式数据持续追加，与系统的实时监控模块匹配。

**Q3：系统配置表为什么不做成应用配置文件？**

A：① 数据库存储支持 Web 界面在线修改、即时生效，无需停机重启；② 历史变更可通过 `created_at` / `updated_at` 字段审计；③ 多实例部署场景下避免配置漂移；④ 业务参数（如排序权重）属于"运行时可调"而非"启动期固定"参数，存数据库更合理。
